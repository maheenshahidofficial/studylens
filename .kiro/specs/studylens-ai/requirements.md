# Requirements Document

## Introduction

StudyLens AI is a web application that helps university students determine whether their study materials adequately cover their course syllabus before an exam. Students upload PDF files of their lecture notes and course syllabus. The system uses AI to extract key concepts from both documents, compares them against each other to classify topics as covered, partially covered, or missing, identifies knowledge gaps, and produces an explainable exam-readiness report alongside a personalized revision plan.

The MVP focuses on PDF upload, text extraction, AI-driven concept extraction, syllabus matching, knowledge-gap detection, readiness scoring, and revision planning. The backend is built with Python and Flask, the frontend with responsive HTML/CSS/JavaScript, and the database with SQLite.

---

## Glossary

- **Student**: An authenticated user of the StudyLens AI platform.
- **Study Material**: A PDF document uploaded by the Student containing lecture notes or revision content.
- **Syllabus**: A PDF document uploaded by the Student that defines the official topics and learning outcomes for a course.
- **Upload Service**: The backend component responsible for receiving, validating, and storing uploaded PDF files.
- **Extraction Engine**: The backend component responsible for converting PDF binary content into plain text.
- **AI Analyzer**: The AI-powered backend component responsible for extracting concepts, matching topics, detecting knowledge gaps, and computing readiness scores.
- **Topic**: A distinct subject area or learning outcome identified within the Syllabus.
- **Concept**: A key idea, term, or fact extracted from the Study Material or Syllabus by the AI Analyzer.
- **Coverage Status**: A classification of a Topic as one of: `covered`, `partially_covered`, or `missing`.
- **Knowledge Gap**: A Topic present in the Syllabus whose Coverage Status is `missing` or `partially_covered`.
- **Readiness Score**: A numeric value between 0 and 100 representing the percentage of Syllabus Topics with a `covered` status.
- **Readiness Report**: A structured document generated by the AI Analyzer that presents Coverage Status for each Topic and explains the reasoning behind each classification.
- **Revision Plan**: A prioritized, actionable list of study tasks generated by the AI Analyzer based on Knowledge Gaps and Topic importance.
- **Analysis Session**: A single end-to-end run of the analysis pipeline for one Study Material and one Syllabus, associated with a Student.
- **Session History**: The record of all Analysis Sessions previously completed by a Student.

## Requirements

---

### Requirement 1: Student Account Management

**User Story:** As a student, I want to register and log in to StudyLens AI, so that my analysis sessions and revision plans are saved and accessible only to me.

#### Acceptance Criteria

1. THE Upload_Service SHALL provide a registration endpoint that accepts a unique email address and a password between 8 and 128 characters inclusive.
2. WHEN a registration request is received with an email address already associated with an existing account, THE Upload_Service SHALL return an error response with HTTP status 409 and a message indicating the email is already registered.
3. WHEN a registration request is received with a password shorter than 8 characters or longer than 128 characters, THE Upload_Service SHALL return an error response with HTTP status 400 and a message specifying the password length constraints.
4. WHEN a registration request is received with a malformed email address that does not conform to the format local-part@domain, THE Upload_Service SHALL return an error response with HTTP status 400 and a message indicating the email format is invalid.
5. WHEN a valid registration request is received, THE Upload_Service SHALL store a bcrypt-hashed representation of the password and SHALL NOT store the plaintext password.
6. WHEN a login request is received with a valid email and correct password, THE Upload_Service SHALL return a session token that expires after 24 hours.
7. WHEN a login request is received with an unrecognised email or an incorrect password, THE Upload_Service SHALL return an error response with HTTP status 401 and a message indicating that the credentials are invalid.
8. WHILE a Student is authenticated, THE Upload_Service SHALL associate all Analysis Sessions with that Student's account.
9. WHEN a Student's session token has expired, THE Upload_Service SHALL reject subsequent authenticated requests with HTTP status 401 and a message indicating that the session has expired.

### Requirement 2: PDF File Upload

**User Story:** As a student, I want to upload my study material and course syllabus as PDF files, so that the system can analyse them.

#### Acceptance Criteria

1. WHILE a Student is authenticated, THE Upload_Service SHALL accept a multipart form request containing one Study Material PDF and one Syllabus PDF, where each file is submitted as a distinct named form field.
2. IF a multipart form request is submitted with a missing Study Material PDF or a missing Syllabus PDF, THEN THE Upload_Service SHALL reject the request and return an error response indicating which required file is absent.
3. WHEN an uploaded file has a MIME type other than `application/pdf`, THE Upload_Service SHALL reject the file and return an error response with HTTP status 415 and a message identifying which file is invalid.
4. WHEN an uploaded file exceeds 20 MB in size, THE Upload_Service SHALL reject the file and return an error response with HTTP status 413 and a message identifying which file exceeds the size limit.
5. WHEN both uploaded files are valid, THE Upload_Service SHALL store each file under a path scoped to the Student's account identifier and a newly generated unique session identifier, and return a response containing that session identifier.
6. WHEN a file upload is interrupted or fails mid-transfer, THE Upload_Service SHALL discard any partially written data and return an error response with HTTP status 500.
7. THE Upload_Service SHALL accept PDF files that contain either embedded text or scanned image pages.
8. IF a Student is not authenticated, THEN THE Upload_Service SHALL reject the upload request and return an error response with HTTP status 401.

---

### Requirement 3: Text Extraction from PDFs

**User Story:** As a student, I want the system to extract readable text from my uploaded PDFs, so that the AI can analyse the content.

#### Acceptance Criteria

1. WHEN a valid Study Material PDF is stored, THE Extraction_Engine SHALL extract all readable text from the document and store the extracted text associated with the Analysis Session.
2. WHEN a valid Syllabus PDF is stored, THE Extraction_Engine SHALL extract all readable text from the document and store the extracted text associated with the Analysis Session.
3. WHEN a PDF contains embedded selectable text, THE Extraction_Engine SHALL extract that text without requiring OCR.
4. WHEN a PDF contains scanned image pages with no embedded selectable text, THE Extraction_Engine SHALL apply OCR to extract text from those pages.
5. IF text extraction fails for every page of a PDF, THEN THE Extraction_Engine SHALL record the failure in the Analysis Session and return an error response indicating the file could not be processed.
6. WHEN text extraction produces fewer than 100 characters from a document, THE Extraction_Engine SHALL flag the result as potentially insufficient and include a warning in the Readiness Report.
7. WHEN a PDF contains both embedded selectable text pages and scanned image pages, THE Extraction_Engine SHALL extract selectable text directly from text-bearing pages and apply OCR to image-only pages, combining the results into a single extracted text output associated with the Analysis Session.
8. IF text extraction for one or more pages of a PDF succeeds but at least one page fails, THEN THE Extraction_Engine SHALL store the successfully extracted text, record the count of failed pages in the Analysis Session, and include a warning in the Readiness Report indicating partial extraction occurred.
9. IF a stored PDF exceeds 500 pages, THEN THE Extraction_Engine SHALL return an error response indicating the document exceeds the maximum supported page limit and record the failure in the Analysis Session.

### Requirement 4: AI-Powered Concept Extraction

**User Story:** As a student, I want the system to identify the key concepts and topics in my uploaded documents, so that a meaningful comparison can be made.

#### Acceptance Criteria

1. WHEN extracted text from the Syllabus is available, THE AI_Analyzer SHALL identify and return a structured list of between 1 and 200 Topics from that text.
2. WHEN extracted text from the Study Material is available, THE AI_Analyzer SHALL identify and return a structured list of between 1 and 200 Concepts from that text.
3. THE AI_Analyzer SHALL associate each Topic with an importance level of `high`, `medium`, or `low` based on signals such as weighting, repetition, and explicit emphasis in the Syllabus text.
4. WHEN the Syllabus text contains fewer than three identifiable Topics, THE AI_Analyzer SHALL include a warning in the Analysis Session indicating that the Syllabus may be too sparse for meaningful analysis.
5. THE AI_Analyzer SHALL complete concept extraction for both documents within 60 seconds of receiving the extracted text.
6. IF concept extraction for one or both documents fails, THEN THE AI_Analyzer SHALL record the failure in the Analysis Session, preserve any successfully extracted results, and return an error response indicating which document's extraction failed.
7. IF concept extraction does not complete within 60 seconds, THEN THE AI_Analyzer SHALL cancel the extraction, mark the Analysis Session as failed, and return an error response indicating the extraction timed out.

---

### Requirement 5: Syllabus-to-Material Coverage Matching

**User Story:** As a student, I want to know which syllabus topics my study material covers, partially covers, or misses entirely, so that I can see where my preparation stands.

#### Acceptance Criteria

1. WHEN Topic and Concept lists are extracted and stored for an Analysis Session, THE AI_Analyzer SHALL assign a Coverage Status to each Topic.
2. IF all key points of a Topic have at least one corresponding Concept mapped from the Study Material, THEN THE AI_Analyzer SHALL classify that Topic as `covered`.
3. IF at least one but not all key points of a Topic have a corresponding Concept mapped from the Study Material, THEN THE AI_Analyzer SHALL classify that Topic as `partially_covered`.
4. IF no Concept is mapped to a Topic, THEN THE AI_Analyzer SHALL classify that Topic as `missing`.
5. THE AI_Analyzer SHALL produce a coverage summary that states the total number of Topics and the count of Topics in each Coverage Status category.
6. WHEN coverage matching is complete, THE AI_Analyzer SHALL record the Coverage Status for each Topic in the Analysis Session.

---

### Requirement 6: Knowledge Gap Detection

**User Story:** As a student, I want the system to explicitly identify my knowledge gaps, so that I know exactly which areas I need to study more.

#### Acceptance Criteria

1. WHEN coverage matching is complete, THE AI_Analyzer SHALL produce a Knowledge Gap list containing every Topic whose Coverage Status is `missing` or `partially_covered`.
2. THE AI_Analyzer SHALL rank Knowledge Gaps using the following six-tier priority order, from highest to lowest: (1) `missing` + `high` importance, (2) `missing` + `medium` importance, (3) `missing` + `low` importance, (4) `partially_covered` + `high` importance, (5) `partially_covered` + `medium` importance, (6) `partially_covered` + `low` importance.
3. THE AI_Analyzer SHALL include for each Knowledge Gap an explanation of no more than 100 words identifying which required concepts or subtopics are absent or insufficiently addressed in the Study Material.
4. WHEN no Knowledge Gaps are detected, THE AI_Analyzer SHALL record an empty Knowledge Gap list and include a message in the Readiness Report confirming full coverage.
5. IF coverage matching fails to complete, THEN THE AI_Analyzer SHALL mark the Analysis Session as failed, record the failure reason, and return an error response indicating that knowledge gap detection could not proceed.

---

### Requirement 7: Exam Readiness Report Generation

**User Story:** As a student, I want to receive an explainable exam-readiness report, so that I can understand my current preparation level and why certain topics are flagged.

#### Acceptance Criteria

1. WHEN knowledge gap detection is complete, THE AI_Analyzer SHALL generate a Readiness Report for the Analysis Session.
2. THE AI_Analyzer SHALL include the Readiness Score in the Readiness Report, computed as `(number of Topics with Coverage Status "covered" / total number of Topics) × 100`, rounded to the nearest integer.
3. THE AI_Analyzer SHALL include in the Readiness Report the Coverage Status and a plain-language reasoning of between 1 and 3 sentences for every Topic in the Analysis Session.
4. THE AI_Analyzer SHALL include in the Readiness Report a ranked Knowledge Gap list as defined in Requirement 6.
5. WHEN the Readiness Score is below 50, THE AI_Analyzer SHALL include a prominent alert in the Readiness Report advising the Student to review the missing and partially covered topics before the exam.
6. IF the Readiness Score is between 50 and 69 inclusive, THEN THE AI_Analyzer SHALL include in the Readiness Report a caution notice advising the Student that preparation is partial and listing the partially covered Topics.
7. THE AI_Analyzer SHALL complete Readiness Report generation within 30 seconds of completing knowledge gap detection.
8. THE AI_Analyzer SHALL store the Readiness Report in the Analysis Session record in the SQLite database.
9. IF Readiness Report generation fails or exceeds the 30-second time limit, THEN THE AI_Analyzer SHALL mark the Analysis Session as failed and return an error response indicating the report could not be generated, without discarding any previously stored Analysis Session data.

---

### Requirement 8: Personalized Revision Plan Generation

**User Story:** As a student, I want to receive a personalized revision plan based on my knowledge gaps, so that I have a clear, prioritized study schedule.

#### Acceptance Criteria

1. WHEN the Readiness Report is generated, THE AI_Analyzer SHALL generate a Revision Plan for the Analysis Session.
2. WHEN the Readiness Report is generated, THE AI_Analyzer SHALL include in the Revision Plan one revision task per Knowledge Gap, ordered by the Knowledge Gap priority ranking defined in Requirement 6, where each task references the associated Knowledge Gap identifier.
3. WHEN the Readiness Report is generated, THE AI_Analyzer SHALL include in each revision task a description identifying the Topic to study and the reason derived from the detected Knowledge Gap evidence.
4. WHEN the Readiness Report is generated, THE AI_Analyzer SHALL assign an estimated study duration in minutes to each revision task, based on the Topic importance level: 60 minutes for `high`, 30 minutes for `medium`, and 15 minutes for `low`.
5. WHEN the Readiness Report is generated, THE AI_Analyzer SHALL include a total estimated revision time in the Revision Plan, computed as the sum of all individual task durations.
6. IF no Knowledge Gaps exist at the time of Readiness Report generation, THEN THE AI_Analyzer SHALL generate a Revision Plan containing a single maintenance task with a description recommending the Student review all covered Topics before the exam and an estimated duration of 30 minutes.
7. WHEN the Revision Plan is generated, THE AI_Analyzer SHALL store the Revision Plan in the Analysis Session record in the SQLite database.
8. IF the Revision Plan fails to generate or fails to store in the Analysis Session record, THEN THE AI_Analyzer SHALL leave the Analysis Session Revision Plan empty and include an error indication in the Analysis Session record stating that Revision Plan generation was unsuccessful.

### Requirement 9: Analysis Session History

**User Story:** As a student, I want to view my past analysis sessions, so that I can track my exam readiness over time.

#### Acceptance Criteria

1. WHILE a Student is authenticated, THE Upload_Service SHALL provide an endpoint that returns a list of all Analysis Sessions associated with that Student, ordered by creation date descending, returning an empty list when no sessions exist.
2. WHEN the session history list is requested, THE Upload_Service SHALL include for each Analysis Session the session identifier, course name (if provided), upload date, Readiness Score, and Coverage Status summary, with the list capped at a maximum of 100 sessions per response.
3. WHILE a Student is authenticated, THE Upload_Service SHALL provide an endpoint that returns the full Readiness Report and Revision Plan for a specified Analysis Session identifier.
4. WHEN an Analysis Session identifier is requested that does not belong to the authenticated Student, THE Upload_Service SHALL return an error response with HTTP status 403 without revealing whether the session exists.
5. WHEN an Analysis Session identifier is requested that does not exist, THE Upload_Service SHALL return an error response with HTTP status 404.
6. IF the session history endpoint fails to retrieve data from the data store within 5 seconds, THEN THE Upload_Service SHALL return an error response with HTTP status 503 without returning partial data.

### Requirement 10: Responsive Web Frontend

**User Story:** As a student, I want a clear and usable web interface on both desktop and mobile, so that I can use StudyLens AI from any device.

#### Acceptance Criteria

1. THE Frontend SHALL render correctly and remain fully functional at viewport widths of 375 px, 768 px, and 1280 px, with no horizontal scrollbar, no overlapping elements, and all interactive controls reachable by touch or pointer.
2. THE Frontend SHALL provide a file upload form that accepts exactly one Study Material PDF and one Syllabus PDF, and SHALL reject any file that is not a PDF by displaying a validation error indicating the expected file type before the request is submitted.
3. WHEN an analysis request is submitted, THE Frontend SHALL display a loading indicator within 300 ms and SHALL keep the submit control disabled until the analysis is complete or an error is returned.
4. WHEN the Readiness Report is received, THE Frontend SHALL display the Readiness Score, per-topic Coverage Status, and Knowledge Gap list.
5. WHEN the Revision Plan is received, THE Frontend SHALL display the ordered revision tasks with their descriptions and estimated durations.
6. WHEN the backend returns an error response, THE Frontend SHALL display a human-readable error message describing the nature of the failure and SHALL NOT display a raw HTTP status code, exception class name, or stack trace to the Student.
7. THE Frontend SHALL meet WCAG 2.1 Level AA colour contrast requirements for all text and interactive elements, verified against the WCAG 2.1 SC 1.4.3 contrast ratio thresholds of at least 4.5:1 for normal text and at least 3:1 for large text and UI components.
8. IF a submitted PDF file exceeds 20 MB, THEN THE Frontend SHALL reject the file before upload, display an error indicating the file size limit, and restore the file input to its empty state.

---

### Requirement 11: Analysis Pipeline Reliability

**User Story:** As a student, I want the analysis to complete reliably and within a reasonable time, so that I am not left waiting indefinitely.

#### Acceptance Criteria

1. THE AI_Analyzer SHALL complete the full analysis pipeline — concept extraction, coverage matching, gap detection, report generation, and revision plan generation — within 120 seconds of receiving extracted text for both documents.
2. IF the AI_Analyzer does not receive a response from the external AI service within 60 seconds for any single pipeline stage, THEN THE AI_Analyzer SHALL mark the Analysis Session as failed, store a failure reason indicating which stage timed out, and return an error response indicating a gateway timeout.
3. IF the external AI service returns an error response for any pipeline stage, THEN THE AI_Analyzer SHALL mark the Analysis Session as failed, store a failure reason indicating the affected stage and the nature of the error, and return an error response indicating a service failure.
4. WHEN an Analysis Session is marked as failed, THE Frontend SHALL display a message informing the Student that the analysis failed, indicating the reason, and providing a retry option.
5. THE Upload_Service SHALL limit each authenticated Student to a maximum of 5 concurrent Analysis Sessions.
6. IF an authenticated Student submits a new Analysis Session request while already having 5 concurrent Analysis Sessions in progress, THEN THE Upload_Service SHALL reject the request and return an error response with HTTP status 429 indicating the concurrent session limit has been reached.
